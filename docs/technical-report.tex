\begin{abstract}
OptBin converts supported continuous MPS and CBF models into compact lossless
blocks and loads them through a validating C reader. This report describes the
experimental tool, installation, verification and observed storage/loading
trade-offs. Its practical purpose is repeatable numerical model distribution
and loading, using established compression methods.
\end{abstract}

\section{Implemented scope and contracts}
The package provides MPS-to-OptBin and CBF-to-OptBin converters, a C11 reader,
block traversal, an inspector, Python bindings, and a legacy BQP-to-v2 migration
utility. Make and CMake builds are available. The core requires zlib and uses
the optional Zstandard runtime for compressed blocks; it has no HDF5, CUDA or
solver dependency. The current validated platform is 64-bit little-endian
Linux x86-64. The v2 wire schema and C ABI remain experimental.

The bounded profile preserves LP/QP/QCQP objectives, variable/row bounds and
native quadratic constraints. MPS extensions use producer-specific section
vocabularies~\cite{gurobi,mosek}. QCQP conversion requires an explicit producer
dialect. Gurobi 13.0.3 and MOSEK 11.2.7 reader regressions verify the implemented
\texttt{QCMATRIX}/\texttt{QSECTION} scaling. CPLEX QCQP conventions are not
validated. The continuous CBF 1--3 subset~\cite{cbf} retains scalar cones, original power
parameters, PSD variables and sparse PSD operators. Integrality, change
sequences and unknown features fail explicitly. Storage support is broader than
the optional SCS/Clarabel and Gurobi/SCIP adapter coverage. Full details and
parser exclusions are in \path{README.md} and \path{docs/format-v2.md}.

Text conversion produces a canonical binary64 numerical model; it may sort
coordinates or sum duplicate MPS coefficients. Losslessness refers to exact
reconstruction of that model, including supported signed zeros, rather than
the original text, comments or names. Value blocks select raw, constant, exact
small-integer, exact binary32 or dictionary representations. Integer blocks
use raw or delta/zigzag encodings, followed by optional Zstandard~\cite{zstd}. These are
established techniques integrated for this tool, not a new compressor.

Complete loading validates checksums, array coverage, sparse ordering, shapes,
and cross-array model relationships. Block traversal validates framing, CRCs
and coverage with bounded scratch, but does not establish all cross-array
invariants. CRCs detect accidental corruption and are not authentication.
Conversion uses exclusive publication and never overwrites an existing file.

\section{Build, installation and use}
Native tools require a C11/C++17 toolchain, CMake 3.16+ and zlib development
files. The Zstandard runtime is needed to read Zstd-compressed blocks; write
uncompressed blocks with \texttt{--zstd 0} when it is unavailable. From unpacked
source, a typical local installation is:
\begin{verbatim}
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_SHARED_LIBS=ON
cmake --build build -j4
ctest --test-dir build --output-on-failure
cmake --install build --prefix "$HOME/.local/optbin"
~/.local/optbin/bin/mps2optb examples/qp.mps /tmp/qp.optb
~/.local/optbin/bin/optb_inspect /tmp/qp.optb --load
\end{verbatim}
Installed CMake consumers link \texttt{OptBin::optbin}; an external example is
provided under \path{examples/consumer/}. The installed prefix can be relocated.
The public C entry point is \texttt{optb\_load}; release successful models with
\texttt{optb\_free}. Its limit bounds decoded-array bytes, not process RSS.

The Python distribution requires CPython 3.10+. Source installation needs a C
compiler, Python headers and zlib development files. Pip builds a bundled C
reader, so the installed package works outside its source checkout:
\begin{verbatim}
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/optbin-info /tmp/qp.optb --limit 8589934592
\end{verbatim}
The base binding has no NumPy/SciPy dependency. Optional extras enable solver
adapters and the Python HDF5 experiment; standalone converters and the C
development library use the native installation. Python source/wheel and
relocated native installs are exercised by \path{scripts/check_install.py}.
The wheel has a local Linux platform tag; no manylinux or cross-distribution
binary compatibility is claimed. CI tests CPython 3.10/3.12/3.14, optional
frontends, independent-reader contracts, UBSan and compilation of this note.
Hosted results are available in
\href{https://github.com/PolyU-IOR/OptBin/actions}{GitHub Actions}.

\section{Compressed storage and complete loading}
The practical comparison uses MPS.gz or CBLIB CBF.gz, externally gzipped raw
HDF5 arrays~\cite{hdf5} (\texttt{raw.h5.gz}), default OptBin and externally gzipped default
OptBin (\texttt{OptBin.gz}). Raw HDF5 contains unencoded binary64 values,
32/64-bit indices, metadata and block checksums, with no dataset compression or
shuffle filter. External gzip is applied to the entire file. HDF5 is 1.14.6.

MPS.gz timing uses public \texttt{gurobipy.read} from Gurobi 13.0.3~\cite{gurobiread},
ending with its solver model ready. Environment startup and subsequent
reference extraction are measured separately. CBF.gz uses public MOSEK 11.2.7
\texttt{Task.readdata}~\cite{mosekread}, ending with its solver Task ready.
Full conic functions, domains and PSD trace coefficients agree exactly with
OptBin after explicit coordinate normalization. All public-API extraction and
comparison occur outside read timing. The binary paths return numeric arrays
that pass full \texttt{optb\_validate}; binary checksums are also verified.
These are practical public loader endpoints with different internal model
representations. No optimization, presolve, GPU upload or model-file output is
timed. Numerical comparisons occur after the timer and RSS snapshot.
Files are warm; trials use fresh processes in shuffled rounds.
Only large-case RSS is interpreted: small subprocess peaks can retain a
pre-exec parent watermark, rather than reflect minimum reader memory.

The binary gzip paths decompress to a seekable temporary file on the same
filesystem before native loading, with both steps included in the timer.
\texttt{OptBin.gz} is a transport wrapper: the C API itself expects the expanded
\texttt{.optb} file. Generated gzip files use level 6; existing CBLIB gzip settings are unknown.
Gzip creation times are recorded separately as preparation;
they are not charged to repeated loading. The default OptBin writer already
uses block encodings and Zstandard. This compares practical representations,
not isolated compressors or all possible HDF5 reader implementations.

Before gzip, raw HDF5 occupies 27.99 and 26.32 GiB (prod/mcf), 63.4 and 5.9 times default OptBin. The tested raw.h5.gz loader needs a temporary file of that expanded size; default OptBin reads its internally compressed file directly. These savings concern stored files and temporary disk space; decoded RAM is essentially unchanged. HDF5 also supports internal dataset compression, which this raw-array baseline does not use.

For \texttt{mcf\_5000\_100\_1000}, raw.h5.gz is smaller than both OptBin representations; stored size and loading time favor different choices. Default OptBin loads 6.44 and 7.22 times as fast as Gurobi on these cases; OptBin.gz loads 6.18 and 5.27 times as fast. Creating raw.h5.gz from the existing raw HDF5 files took 208.6 and 48.5 seconds; creating OptBin.gz from the existing OptBin files took 14.8 and 8.3 seconds. These are gzip-only preparation costs, not source-to-binary conversion times.

OptBin peak process RSS is 28.00 and 26.32 GiB; the other binary paths are within 0.01 GiB. Gurobi read-phase RSS is 57.67 and 70.41 GiB. The latter includes the vendor model and its metadata, so this is not a pure container-memory comparison. Expanded numeric arrays dominate memory. RSS excludes filesystem page cache, expanded gzip temporaries and later solver allocations. Full verification temporarily holds additional model and array copies. Binary gzip staging needs temporary space equal to the uncompressed file size.

The prod matrix contains 2,310,559,600 entries. Gurobi reads it successfully; in 13.0.3, \texttt{getA()} then fails while querying the legacy 32-bit nonzero count. Full verification uses public row-only model copies below the query limit, with complete row/nonzero coverage. This extraction work is outside read timing and its RSS snapshot.

\section{Limits, provenance and reproducibility}
Full model loading allocates expanded arrays. The MPS converter uses temporary
section spools; arbitrary-coordinate CBF conversion currently sorts in memory.
There is no v2 GPU adapter, direct storage-to-GPU access or compressed solver
computation. Cold-I/O studies, more large QP/QCQP/PSD workloads, complete
original-coordinate infeasibility certificates and broader portability remain
outside this release.

Source collections retain their identifiers, attribution and licenses:
Oliver Hinder's large LPs\footnote{\url{https://www.oliverhinder.com/large-scale-lp-problems}},
QPLIB\footnote{\url{https://qplib.zib.de/}} and
CBLIB\footnote{\url{https://cblib.zib.de/}}.
The software is MIT licensed; external datasets are not bundled or relicensed.
Benchmark datasets must be obtained separately; source identifiers and verified
file hashes are retained in the benchmark reports.
